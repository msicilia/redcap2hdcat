Imports and vocabularies (needed for meaningful validation)
  - The shapes owl:imports the DCAT-AP 3.0.0 shapes:
      shapes/*-shapes.ttl          -> https://semiceu.github.io/DCAT-AP/releases/3.0.0/html/shacl/shapes.ttl
      ranges/range.ttl             -> .../3.0.0/html/shacl/range.ttl
      recommended/public- and non-public-shapes_recommended.ttl -> .../3.0.0/html/shacl/shapes_recommended.ttl
        (restricted-shapes_recommended.ttl does NOT import it)
    The validator maps these to the bundled copies ehds/catalogue/shapes.ttl, range.ttl, shapes_recommended.ttl and
    mdr-vocabularies.shape.ttl. These copies are LOCALLY MODIFIED relative to upstream SEMIC 3.0.0:
    - catalogue/shapes.ttl: skos:ConceptScheme title uses sh:alternativePath (dct:title|skos:prefLabel|rdfs:label);
      one datatype changed from xsd:decimal to xsd:nonNegativeInteger.
    - The other three differ in bytes; range.ttl differs only in whitespace.
    Use the bundled copies, not upstream, to reproduce the official validator.
  - imports/imports.ttl owl:imports the ontologies (dcat2, DC terms, FOAF, LOCN, SPDX, PROV-O, OWL-Time, vCard, ADMS,
    DQV, CSVW, m8g). They are bundled as ehds/catalogue/{dcat2.ttl, dublin_core_terms.ttl, index.rdf, locn.ttl,
    spdx-ontology.owl.rdf, prov-o.ttl, time.ttl, ns.ttl, adms.ttl, dqv.ttl, csvw.ttl, m8g.ttl, schema.ttl, eli.rdf}.
  - imports/mdr_imports.ttl owl:imports the controlled vocabularies. This matters because
    controlled-vocabularies/mdr-vocabularies.shape.ttl checks NAL membership with
    sh:node [ sh:property [ sh:path skos:inScheme ; sh:hasValue <scheme> ] ], so the concept data must be in the data graph.
    Snapshots bundled in the release (ehds/catalogue/):
      EU Publications Office NALs: languages.rdf (language), corporatebodies.rdf (corporate-body), continents.rdf,
        countries.rdf, dataset-types.rdf, data-theme.rdf, filetypes.rdf, frequencies.rdf, places.rdf,
        planned-availability.rdf, access-right.rdf, distribution-status.rdf
        (IRIs http://publications.europa.eu/resource/authority/<name>)
      ADMS: ADMS_SKOS_v1.00.rdf (https://github.com/SEMICeu/ADMS-AP/raw/master/purl.org/ADMS_SKOS_v1.00.rdf; publisher type)
      DG SANTE HealthData@EU CVs (https://hdeu-dcat.data.health.europa.eu/resource/authority/<name>):
        healthcategories.rdf, publisher-type.rdf, health-theme.rdf, health-activity.rdf, coding-system.rdf, standard.rdf
    Personal data (dpv:hasPersonalData) is checked only by an IRI regex (^https://w3id.org/dpv/dpv-pd#.+), so DPV does not need to be loaded.
    Skipped import: http://publications.europa.eu/ontology/euvoc (validator.owlImportSkippedUris).
    We did NOT download live versions of the NALs/CVs. The release-bundled snapshots ARE the vocabularies the official
    validator config uses, which is the reproducible choice. They therefore live in release-8/ehds/catalogue/ and not
    in a separate vocabularies/ folder.
    Also bundled but not referenced by config.properties: dcat-ap_2.0.1.rdf, geodcat-ap-SHACL.ttl.
  - The ehds/catalogue copy of the ADMS/DQV/etc. imports keeps the reproduction offline.
